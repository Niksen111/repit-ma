# Repit MA

Веб-приложение для взаимодействия преподавателей и учеников.

## Технологии

- JDK 21, Kotlin и Spring Boot;
- Spring Security;
- MyBatis и Liquibase;
- SQLite;
- TypeScript, Vite и pnpm;
- Gradle Wrapper;
- Docker и Docker Compose.

## Локальный запуск

Потребуются JDK 21, Node.js 22 и pnpm 11.

Запустите backend из корня проекта:

```powershell
.\gradlew.bat :app:bootRun
```

В отдельном терминале установите зависимости и запустите frontend:

```powershell
cd frontend
pnpm install --frozen-lockfile
pnpm dev
```

Frontend доступен по адресу `http://localhost:5173`, backend — `http://localhost:8080`. Vite перенаправляет запросы `/api` на backend.

По умолчанию SQLite хранится в файле `repit-ma.db` в корне проекта. Путь можно изменить переменной окружения `REPIT_MA_DATABASE_PATH`.

При первой миграции создаётся пользователь `admin` с ролью `ADMIN`. Хеш его пароля задан в Liquibase changeset.

## Запуск в Docker

```bash
docker compose up --build
```

Приложение доступно по адресу `http://localhost:8080`. База SQLite сохраняется в каталоге `data`.

Остановка контейнера:

```bash
docker compose down
```

## Занятия, расписание и оплата

В курсе ученика и преподавателя сразу открываются материалы выбранного занятия.
При входе без ссылки выбирается ближайшее будущее неотменённое занятие;
если будущих нет — последнее прошедшее. Ссылка из расписания открывает указанное занятие.
Кнопка **Выбрать занятие** раскрывает список с пагинацией по пять занятий
на компьютере и телефоне. После выбора список сворачивается. Настройка расписания
и создание занятий доступны преподавателю в блоке **Расписание и новые занятия**.

Для преподавателя и администратора в меню доступно **Расписание** (`/schedule`).
По умолчанию таблица показывает прошедшие занятия; фильтр позволяет посмотреть
будущие или все занятия. Расписание разбито на страницы по пять занятий;
переключение доступно над и под таблицей на компьютере и телефоне. Смена фильтра
открывает первую страницу, сохранение статуса, оплаты или чека сохраняет текущую.
Ссылка на название открывает выбранное занятие в курсе.

Дата и время занятия задаются и отображаются по Москве (`Europe/Moscow`),
независимо от часового пояса сервера или браузера.
До указанного времени статус — **Запланировано**, начиная с этого времени —
**Прошедшее**. Преподаватель может отметить прошедшее занятие как **Проведено**
или **Отменено**, а будущее — как **Отменено**. Выбор автоматического статуса
в списке отменяет ручную отметку. Чтобы перенести проведённое занятие в будущее,
сначала нужно вернуть ему автоматический статус.

Статус, отметка **Оплачено** и чеки доступны в таблице и карточке занятия.
Изменения сохраняются сразу. Оплата учитывается независимо от статуса занятия
и наличия чека. Преподаватель может прикреплять и удалять чеки (до 25 МиБ каждый);
ученик видит статус и оплату и может скачать чеки своего курса.
Чеки хранятся отдельно от учебных материалов, внутри SQLite.

API: `GET /api/schedule` — расписание преподавателя;
`PUT /api/courses/{courseId}/lessons/{lessonId}/tracking` — частичное обновление
полей `outcome` (`AUTO`, `HELD`, `CANCELLED`) и `paid` (`true`/`false`).
API файлов поддерживает `ownerType=RECEIPT`, где `ownerId` — ID занятия.

## Повторяющиеся занятия

На странице **Ученики** у каждого курса доступны кнопки **Расписание**
и **Разовое занятие**. Расписанием также можно управлять на странице курса.
В одном расписании можно задать несколько дней и времён, включая несколько
занятий в один день. Название и описание заполняются автоматически, их можно
изменить при создании. Дата начала обязательна, дата окончания необязательна.

Занятия создаются сразу на ближайшие семь дней, затем приложение ежедневно
в **03:00 МСК** дополняет этот период. При старте приложения недостающие будущие
занятия тоже создаются; занятия за время простоя задним числом не добавляются.
Созданные занятия помечены **По недельному расписанию** и редактируются как обычные.

Карточка расписания показывает дни и время, срок действия и состояние.
**Остановить расписание** прекращает создание новых занятий. В диалоге можно
также отменить уже созданные будущие занятия этого расписания; история, оплата
и материалы сохраняются. Остановленное расписание можно возобновить.
Кнопка **Расписание** открывает существующее расписание с заполненными днями,
временем, датами, названием и описанием. Если расписаний несколько, в форме
можно выбрать нужное или создать новое. Изменения применяются к дальнейшей
генерации; уже созданные занятия сохраняют свои даты, материалы, статусы и оплату.
Остановленное расписание после редактирования остаётся остановленным.

Повторные и одновременные запуски генерации не создают дубликаты. Отдельная запись
о каждом занятии сохраняется даже после его удаления или переноса, поэтому
генератор не восстанавливает его на исходную дату. Отменённые занятия также
не создаются заново при возобновлении расписания. Если на нужное время уже есть
разовое занятие курса, оно сохраняется и второе занятие не создаётся.

API для преподавателя курса и администратора:

- `GET /api/courses/{courseId}/recurring-lessons` — список расписаний;
- `POST /api/courses/{courseId}/recurring-lessons` — создание: `slots` содержит
  `dayOfWeek` (1 — понедельник, 7 — воскресенье) и `startTime` (`HH:mm`);
  необязательные поля — `title`, `description`, `startDate`, `endDate`;
- `PUT /api/courses/{courseId}/recurring-lessons/{scheduleId}` — редактирование
  тех же полей существующего расписания;
- `PUT /api/courses/{courseId}/recurring-lessons/{scheduleId}/active` — поля
  `active` и необязательное `cancelUpcoming` (при остановке).

Настройки задачи: `REPIT_MA_RECURRING_LESSONS_CRON` (Spring cron, по умолчанию
`0 0 3 * * *`, всегда МСК) и `REPIT_MA_RECURRING_LESSONS_ENABLED` (по умолчанию
`true`). Выключение фоновой задачи не отключает создание занятий при сохранении
или возобновлении расписания.

## Логирование

В Kotlin-коде используется `KotlinLogging.logger {}` из `kotlin-logging-jvm`.
Это обёртка над SLF4J; вывод и настройку обеспечивает стандартный Logback
из Spring Boot. Сообщения записываются через `logger.info { "..." }`, ошибки —
через `logger.error(exception) { "..." }`, чтобы сохранить стек исключения.
Лямбда сообщения вычисляется только при включённом уровне логирования.

Логи выводятся в консоль и доступны через Docker logs. Уровни можно настроить
обычными свойствами Spring Boot, например
`logging.level.ru.niksen111.repitma.courses=DEBUG`.
