# Занятия, домашние задания и решения

Модуль `courses` содержит занятия, домашние задания, решения и их вложения.
`users` отвечает за пользователей, `auth` — за настройку аутентификации,
`app` собирает приложение и содержит общие HTTP-обработчики и миграции.
Дополнительный модуль или универсальный слой репозиториев для этих сущностей не нужен.

Контроллеры разделены по ресурсам: `LessonsController`, `TasksController`,
`SolutionsController`, `FilesController`. Они принимают логин через
`@CurrentUsername` — метааннотацию Spring Security над `@AuthenticationPrincipal`.
Сервисы получают обычные параметры; получение пользователя из глобального
`SecurityContext` внутри бизнес-логики не требуется.

Проверка участника курса и принадлежности ресурсов курсу находится в
`CourseAccessService`. Сервисы операций обращаются к нему и к конкретным мапперам,
без цепочки зависимостей `FileService → SolutionService → TaskService → LessonService`.
Мапперы основных сущностей возвращают модели; сервисы преобразуют их в DTO.

## Связи и права

- Курс содержит занятия; занятие — произвольное число домашних заданий.
- У домашнего задания не более одного решения: внешний ключ и уникальность `solutions.task_id`.
- Преподаватель курса и администратор управляют занятиями, домашками и оценками.
- Решение и его файлы изменяет только ученик соответствующего курса, до первой оценки.
- И зачёт, и незачёт блокируют изменения ученика. Преподаватель может исправить оценку и комментарий.
- Чужой курс или ресурс из другого курса возвращает 404, запрещённая операция участника — 403,
  изменение оценённого решения — 409.

## Файлы и транзакции

`course_files` хранит бинарные данные и метаданные. Таблицы
`lesson_files`, `task_files`, `solution_files`, `lesson_receipts` сохраняют полноценные внешние ключи
на владельцев. Выбор связи находится в Kotlin: `FileService` явно вызывает
`attachFile`, `detachFile` и `findFiles` соответствующего маппера.
В XML нет ветвления по типу владельца.

Сохранение файла и связи выполняется в одной транзакции. Удаление сначала явно
снимает выбранную связь, затем удаляет бинарные данные, если ссылок больше нет.
Сбой любой части откатывает всю операцию.

Внешние ключи SQLite включены для каждого соединения. В БД нет каскадного удаления.
При удалении занятия код явно удаляет его домашки, решения и вложения.
При удалении домашки удаляются её решение и вложения, включая оценённое решение.
Все шаги выполняются в одной транзакции; сбой откатывает всё удаление.
Файлы с сохранившимися ссылками на другие ресурсы остаются в хранилище.
Изменение решения, его файлов и выставление оценки выполняются в транзакциях.
При текущей конфигурации SQLite с одним соединением в пуле эти операции последовательны.

Максимальный размер файла — 25 МиБ. Лимит задан и на HTTP-уровне, и в сервисе.
Файлы выдаются как скачиваемые вложения с UTF-8-именами. Для SQLite маппер
использует `ByteArrayTypeHandler`, так как JDBC-драйвер не поддерживает `getBlob`.

BLOB-хранилище подходит для начального небольшого объёма материалов: база и вложения
резервируются вместе. При росте объёма стоит вынести бинарные данные в файловое
или объектное хранилище; сейчас отдельный интерфейс хранилища не вводится.

## API

Все пути начинаются с `/api/courses/{courseId}`.

| Ресурс | Методы и путь |
| --- | --- |
| Занятия | GET, POST `/lessons`; PUT, DELETE `/lessons/{lessonId}` |
| Домашки занятия | GET, POST `/lessons/{lessonId}/tasks` |
| Домашка | PUT, DELETE `/tasks/{taskId}` |
| Решение домашки | GET, POST `/tasks/{taskId}/solution` |
| Изменение решения | PUT `/solutions/{solutionId}` |
| Оценка | PUT `/solutions/{solutionId}/grade` |
| Статус и оплата занятия | PUT `/lessons/{lessonId}/tracking` |
| Личная заметка преподавателя | GET, PUT `/teacher-note` |
| Список/загрузка файлов | GET, POST `/files?ownerType=LESSON&ownerId=…` |
| Скачивание/удаление файла | GET, DELETE `/files/{fileId}?ownerType=LESSON&ownerId=…` |

Для файлов допустимы типы владельца `LESSON`, `TASK`, `SOLUTION`, `RECEIPT`;
загрузка использует multipart-поле `file`. POST `/lessons/{lessonId}/task`
сохранён как совместимый вариант пути создания домашки.

Тема занятия и название домашки передаются как `title`. `scheduledAt` —
локальные дата и время ISO без часового пояса, например `2026-09-26T15:00:00`.
Время выставления оценки `gradedAt` записывается как UTC Instant.
В оценке `grade: true` означает зачёт, `false` — незачёт; отсутствие оценки — `null`.

## Интерфейс

На странице `/courses/{courseId}` занятия отображаются от новых к старым.
Выбор занятия загружает его материалы, все домашки, решения и вложения.
Преподаватель и администратор создают, редактируют и удаляют занятия и домашки,
добавляют материалы, выставляют и исправляют оценку и комментарий.
Удаление занятия или домашки требует подтверждения с пояснением об удалении связанных данных.

Ученик отправляет решение с необязательным текстом, затем может прикрепить файлы.
До оценки доступны изменение текста и добавление/удаление файлов.
После зачёта или незачёта эти действия скрываются; оценка и комментарий остаются видны.
Файлы скачиваются через авторизованный запрос, в том числе изображения.
Загрузка нескольких файлов последовательная: успешные сохраняются, ошибки перечисляются.
Файлы добавляются после сохранения занятия, домашки или решения.
Дата занятия сохраняется как локальное время без преобразования в UTC.

`frontend/src/courses-api.ts` содержит типы и HTTP-клиент,
`frontend/src/course-learning.ts` — интерфейс материалов курса.
Команды сборки и тестов описаны в [инструкции для разработки](development.md).

## Занятия, расписание и оплата

В курсе ученика и преподавателя сразу открываются материалы выбранного занятия.
При входе без ссылки выбирается ближайшее будущее неотменённое занятие;
если будущих нет — последнее прошедшее. Ссылка из расписания открывает указанное занятие.
Кнопка **Выбрать занятие** раскрывает список с пагинацией по десять занятий
на компьютере и телефоне. После выбора список остаётся открытым на текущей странице.
В курсе преподавателя содержание выбранного занятия находится над списком занятий,
а сам список сразу раскрыт. Настройка расписания и создание занятий доступны
преподавателю в блоке **Расписание и новые занятия** под списком.

В блоке ученика преподаватель может оставить личный **Комментарий к ученику**:
текст и ссылки длиной до 10 000 символов. По умолчанию заметка показана в одном
блоке для чтения в стиле информации об ученике, сохранённые HTTP/HTTPS-ссылки
доступны для перехода. Кнопка **Редактировать** открывает увеличенное поле
с белым фоном; **Сохранить** возвращает просмотр,
**Отмена** восстанавливает сохранённый текст. Заметка относится к конкретному
курсу, хранится в SQLite и доступна только преподавателю этого курса и администратору.
Ученик и другие преподаватели не могут читать или менять её через API;
общие ответы курса и профиля заметку не содержат.
API: `GET` и `PUT /api/courses/{courseId}/teacher-note`, тело сохранения — `{"note":"..."}`.
Пустая строка очищает заметку. На компьютере блок комментария всегда раскрыт;
на телефоне изначально свёрнут и открывается по нажатию на заголовок.

Для преподавателя и администратора в меню доступно **Расписание** (`/schedule`).
По умолчанию таблица показывает будущие занятия, начиная с ближайшего; фильтр позволяет
посмотреть прошедшие или все занятия. Расписание разбито на страницы по двадцать занятий;
переключение доступно над и под таблицей на компьютере и телефоне. Смена фильтра
открывает первую страницу, сохранение статуса, оплаты или чека сохраняет текущую.
Ссылка на название открывает выбранное занятие в курсе.

Дата и время занятия задаются и отображаются по Москве (`Europe/Moscow`),
независимо от часового пояса сервера или браузера.
До указанного времени статус — **Запланировано**, начиная с этого времени —
**Прошедшее**. Преподаватель может отметить прошедшее занятие как **Проведено**
или **Отменено**, а будущее — как **Отменено**. Выбор автоматического статуса
в списке отменяет ручную отметку. Чтобы перенести проведённое занятие в будущее,
сначала нужно вернуть ему автоматический статус.

Статус, отметка **Оплачено** и чеки доступны в таблице и карточке занятия.
Изменения сохраняются сразу. Оплата учитывается независимо от статуса занятия
и наличия чека. Преподаватель может прикреплять и удалять чеки (до 25 МиБ каждый);
ученик видит статус и оплату и может скачать чеки своего курса.
Чеки хранятся отдельно от учебных материалов, внутри SQLite.

API: `GET /api/schedule` — расписание преподавателя;
`PUT /api/courses/{courseId}/lessons/{lessonId}/tracking` — частичное обновление
полей `outcome` (`AUTO`, `HELD`, `CANCELLED`) и `paid` (`true`/`false`).
API файлов поддерживает `ownerType=RECEIPT`, где `ownerId` — ID занятия.

## Повторяющиеся занятия

На странице **Ученики** у каждого курса доступны кнопки **Расписание**
и **Разовое занятие**. Расписанием также можно управлять на странице курса.
В одном расписании можно задать несколько дней и времён, включая несколько
занятий в один день. Название и описание заполняются автоматически, их можно
изменить при создании. Дата начала обязательна, дата окончания необязательна.

Занятия создаются сразу на ближайшие семь дней, затем приложение ежедневно
в **03:00 МСК** дополняет этот период. При старте приложения недостающие будущие
занятия тоже создаются; занятия за время простоя задним числом не добавляются.
Созданные занятия помечены **По недельному расписанию** и редактируются как обычные.

Карточка расписания показывает дни и время, срок действия и состояние.
**Остановить расписание** прекращает создание новых занятий. В диалоге можно
также отменить уже созданные будущие занятия этого расписания; история, оплата
и материалы сохраняются. Остановленное расписание можно возобновить.
Кнопка **Расписание** открывает существующее расписание с заполненными днями,
временем, датами, названием и описанием. Если расписаний несколько, в форме
можно выбрать нужное или создать новое. Изменения применяются к дальнейшей
генерации; уже созданные занятия сохраняют свои даты, материалы, статусы и оплату.
Остановленное расписание после редактирования остаётся остановленным.

Повторные и одновременные запуски генерации не создают дубликаты. Отдельная запись
о каждом занятии сохраняется даже после его удаления или переноса, поэтому
генератор не восстанавливает его на исходную дату. Отменённые занятия также
не создаются заново при возобновлении расписания. Если на нужное время уже есть
разовое занятие курса, оно сохраняется и второе занятие не создаётся.

API для преподавателя курса и администратора:

- `GET /api/courses/{courseId}/recurring-lessons` — список расписаний;
- `POST /api/courses/{courseId}/recurring-lessons` — создание: `slots` содержит
  `dayOfWeek` (1 — понедельник, 7 — воскресенье) и `startTime` (`HH:mm`);
  необязательные поля — `title`, `description`, `startDate`, `endDate`;
- `PUT /api/courses/{courseId}/recurring-lessons/{scheduleId}` — редактирование
  тех же полей существующего расписания;
- `PUT /api/courses/{courseId}/recurring-lessons/{scheduleId}/active` — поля
  `active` и необязательное `cancelUpcoming` (при остановке).

Настройки задачи: `REPIT_MA_RECURRING_LESSONS_CRON` (Spring cron, по умолчанию
`0 0 3 * * *`, всегда МСК) и `REPIT_MA_RECURRING_LESSONS_ENABLED` (по умолчанию
`true`). Выключение фоновой задачи не отключает создание занятий при сохранении
или возобновлении расписания.
