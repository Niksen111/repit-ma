# Занятия, домашние задания и решения

Модуль `courses` содержит занятия, домашние задания, решения и их вложения.
`users` отвечает за пользователей, `auth` — за настройку аутентификации,
`app` собирает приложение и содержит общие HTTP-обработчики и миграции.
Дополнительный модуль или универсальный слой репозиториев для этих сущностей не нужен.

Контроллеры разделены по ресурсам: `LessonsController`, `TasksController`,
`SolutionsController`, `FilesController`. Они принимают логин через
`@CurrentUsername` — метааннотацию Spring Security над `@AuthenticationPrincipal`.
Сервисы получают обычные параметры; получение пользователя из глобального
`SecurityContext` внутри бизнес-логики не требуется.

Проверка участника курса и принадлежности ресурсов курсу находится в
`CourseAccessService`. Сервисы операций обращаются к нему и к конкретным мапперам,
без цепочки зависимостей `FileService → SolutionService → TaskService → LessonService`.
Мапперы основных сущностей возвращают модели; сервисы преобразуют их в DTO.

## Связи и права

- Курс содержит занятия; занятие — произвольное число домашних заданий.
- У домашнего задания не более одного решения: внешний ключ и уникальность `solutions.task_id`.
- Преподаватель курса и администратор управляют занятиями, домашками и оценками.
- Решение и его файлы изменяет только ученик соответствующего курса, до первой оценки.
- И зачёт, и незачёт блокируют изменения ученика. Преподаватель может исправить оценку и комментарий.
- Чужой курс или ресурс из другого курса возвращает 404, запрещённая операция участника — 403,
  изменение оценённого решения — 409.

## Файлы и транзакции

`course_files` хранит бинарные данные и метаданные. Три таблицы
`lesson_files`, `task_files`, `solution_files` сохраняют полноценные внешние ключи
на владельцев. Выбор связи находится в Kotlin: `FileService` явно вызывает
`attachFile`, `detachFile` и `findFiles` соответствующего маппера.
В XML нет ветвления по типу владельца.

Сохранение файла и связи выполняется в одной транзакции. Удаление сначала явно
снимает выбранную связь, затем удаляет бинарные данные, если ссылок больше нет.
Сбой любой части откатывает всю операцию.

Внешние ключи SQLite включены для каждого соединения. В БД нет каскадного удаления.
При удалении занятия код явно удаляет его домашки, решения и вложения.
При удалении домашки удаляются её решение и вложения, включая оценённое решение.
Все шаги выполняются в одной транзакции; сбой откатывает всё удаление.
Файлы с сохранившимися ссылками на другие ресурсы остаются в хранилище.
Изменение решения, его файлов и выставление оценки выполняются в транзакциях.
При текущей конфигурации SQLite с одним соединением в пуле эти операции последовательны.

Максимальный размер файла — 25 МиБ. Лимит задан и на HTTP-уровне, и в сервисе.
Файлы выдаются как скачиваемые вложения с UTF-8-именами. Для SQLite маппер
использует `ByteArrayTypeHandler`, так как JDBC-драйвер не поддерживает `getBlob`.

BLOB-хранилище подходит для начального небольшого объёма материалов: база и вложения
резервируются вместе. При росте объёма стоит вынести бинарные данные в файловое
или объектное хранилище; сейчас отдельный интерфейс хранилища не вводится.

## API

Все пути начинаются с `/api/courses/{courseId}`.

| Ресурс | Методы и путь |
| --- | --- |
| Занятия | GET, POST `/lessons`; PUT, DELETE `/lessons/{lessonId}` |
| Домашки занятия | GET, POST `/lessons/{lessonId}/tasks` |
| Домашка | PUT, DELETE `/tasks/{taskId}` |
| Решение домашки | GET, POST `/tasks/{taskId}/solution` |
| Изменение решения | PUT `/solutions/{solutionId}` |
| Оценка | PUT `/solutions/{solutionId}/grade` |
| Список/загрузка файлов | GET, POST `/files?ownerType=LESSON&ownerId=…` |
| Скачивание/удаление файла | GET, DELETE `/files/{fileId}?ownerType=LESSON&ownerId=…` |

Для файлов допустимы типы владельца `LESSON`, `TASK`, `SOLUTION`;
загрузка использует multipart-поле `file`. POST `/lessons/{lessonId}/task`
сохранён как совместимый вариант пути создания домашки.

Тема занятия и название домашки передаются как `title`. `scheduledAt` —
локальные дата и время ISO без часового пояса, например `2026-09-26T15:00:00`.
Время выставления оценки `gradedAt` записывается как UTC Instant.
В оценке `grade: true` означает зачёт, `false` — незачёт; отсутствие оценки — `null`.

## Интерфейс

На странице `/courses/{courseId}` занятия отображаются от новых к старым.
Выбор занятия загружает его материалы, все домашки, решения и вложения.
Преподаватель и администратор создают, редактируют и удаляют занятия и домашки,
добавляют материалы, выставляют и исправляют оценку и комментарий.
Удаление занятия или домашки требует подтверждения с пояснением об удалении связанных данных.

Ученик отправляет решение с необязательным текстом, затем может прикрепить файлы.
До оценки доступны изменение текста и добавление/удаление файлов.
После зачёта или незачёта эти действия скрываются; оценка и комментарий остаются видны.
Файлы скачиваются через авторизованный запрос, в том числе изображения.
Загрузка нескольких файлов последовательная: успешные сохраняются, ошибки перечисляются.
Файлы добавляются после сохранения занятия, домашки или решения.
Дата занятия сохраняется как локальное время без преобразования в UTC.

`frontend/src/courses-api.ts` содержит типы и HTTP-клиент,
`frontend/src/course-learning.ts` — интерфейс материалов курса.
Проверка: `pnpm build`; тесты HTTP-клиента: `pnpm test` (Node.js 24+).
