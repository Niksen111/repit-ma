# Разработка и проверки

Команды выполняются из корня репозитория, если не указан переход в `frontend/`.
Инструкции запуска находятся в [главном README](../README.md).

## Проверка

Backend-тесты:

```powershell
.\gradlew.bat test
```

Проверка типов и production-сборка frontend:

```powershell
cd frontend
pnpm build
```

Frontend-тесты (Node.js 24+):

```powershell
cd frontend
pnpm test
```

## Пасхалки интерфейса

Пасхалки реализованы только на фронте в `frontend/src/easter-eggs.ts` и
`frontend/src/easter-eggs.css`, без внешних ресурсов, звуков и запросов к серверу.

- Через 45 секунд бездействия в правом нижнем углу засыпает кот. Нажатие на него
  вызывает «Мур ♥», после чего кот уходит. Работа с формой и открытый диалог
  откладывают его появление; нажатие вне кота или прокрутка убирает его.
- Пять нажатий на логотип запускают гуся на 25 секунд: он догоняет курсор
  или последнее касание и машет крылом. Его можно убрать крестиком.
  Первый переход с внутренней страницы на главную учитывается; на самой главной
  повторные нажатия на логотип не перезагружают страницу.
- Три нажатия на копирайт `© 2026 Repitma` внизу страницы вызывают дождь
  из математических символов. Между нажатиями допускается до 1,6 секунды.

Слой украшений пропускает нажатия к странице, кроме кота и кнопки закрытия гуся.
В фоновой вкладке эффекты и таймеры останавливаются. При `prefers-reduced-motion`
кот и гусь не анимируются, символы появляются статично. Команд с клавиатуры нет.

## Логирование

В Kotlin-коде используется `KotlinLogging.logger {}` из `kotlin-logging-jvm`.
Это обёртка над SLF4J; вывод и настройку обеспечивает стандартный Logback
из Spring Boot. Сообщения записываются через `logger.info { "..." }`, ошибки —
через `logger.error(exception) { "..." }`, чтобы сохранить стек исключения.
Лямбда сообщения вычисляется только при включённом уровне логирования.

Логи выводятся в консоль и доступны через Docker logs. Уровни можно настроить
обычными свойствами Spring Boot, например
`logging.level.ru.niksen111.repitma.courses=DEBUG`.
